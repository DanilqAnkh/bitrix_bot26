# Bitrix24 Documentation Assistant

Telegram-бот для поиска и ответов по официальной документации Bitrix24 API.

Бот принимает текстовые и голосовые сообщения, при необходимости распознаёт голос, ищет релевантную информацию в базе документации Bitrix24 и формирует ответ с помощью YandexGPT.

## Возможности

* ответы на вопросы по документации Bitrix24 API;
* поиск информации через RAG с использованием Yandex AI;
* поддержка текстовых сообщений;
* распознавание голосовых сообщений с помощью Vosk;
* сохранение пользователей и истории сообщений в базе данных;
* автоматическая загрузка актуальной документации Bitrix24 из GitHub;
* отдельная команда для пересборки базы знаний.
* команда /rebuild_kb для пересборки базы знаний прямо из Telegram.

## Установка

Клонировать репозиторий:

```bash
git clone <REPOSITORY_URL>
cd bitrix_chatbot_tg
```

Создать виртуальное окружение:

```bash
python3 -m venv venv
```

Активировать его:

```bash
source venv/bin/activate
```

Обновить pip:

```bash
python -m pip install --upgrade pip
```

Установить зависимости:

```bash
pip install -r requirements.txt
```

## FFmpeg

FFmpeg необходим для обработки аудио, используемого голосовым вводом.

Для Ubuntu/Debian:

```bash
sudo apt update
sudo apt install ffmpeg
```

Проверить установку:

```bash
ffmpeg -version
```

## Vosk

В проекте используется локальная модель Vosk для распознавания русской речи.

Модель должна находиться в:

```text
app/speech/models/
```

Например:

```text
app/speech/models/
└── vosk-model-small-ru-0.22/
```

При запуске бота модель загружается локально и не требует обращения к внешнему API для самого распознавания речи.

## Переменные окружения

Создать файл `.env` в корне проекта по примеру .env.example:
TELEGRAM_BOT_TOKEN=your-token
YANDEX_API_KEY=your-api-key
YANDEX_FOLDER_ID=your-folder-id
YANDEX_MODEL=yandexgpt-5.1
DB_HOST=localhost
DB_PORT=5432
DB_NAME=your-db-name
DB_USER=your-db-user
DB_PASSWORD=your-db-password
YA_SEARCH_INDEX_ID=your-search-index-id #Добавляется автоматически при загрузке базы знаний
ADMIN_IDS=telegram-id

Назначение переменных:

| Переменная           | Назначение                                          |
| -------------------- | --------------------------------------------------- |
| `TELEGRAM_BOT_TOKEN` | токен Telegram-бота                                 |
| `YANDEX_API_KEY`     | API-ключ Yandex Cloud                               |
| `YANDEX_FOLDER_ID`   | идентификатор каталога Yandex Cloud                 |
| `YANDEX_MODEL`       | используемая модель YandexGPT                       |
| `YA_SEARCH_INDEX_ID` | идентификатор Search Index с документацией Bitrix24 |
| `DATABASE_URL`       | строка подключения к PostgreSQL                     |
| `ADMIN_IDS`          | Кому доступна команда /rebuild_kb                   |

Файл `.env` не должен добавляться в Git.

## База данных

Проект использует PostgreSQL для хранения пользователей и истории сообщений.

Перед запуском необходимо создать базу данных и указать её параметры в `DATABASE_URL`.

```bash
createdb bitrix_bot
```

После этого при запуске приложения выполняется инициализация необходимых таблиц.

Применить миграции:

```bash
alembic upgrade head
```

Параметры подключения берутся из переменных DB_* в .env. Строка подключения собирается автоматически в app/config.py.

Создать новую миграцию после изменения моделей:

```bash
alembic revision --autogenerate -m "описание изменений"
alembic upgrade head
```
При запуске python -m app.main схема не создаётся автоматически — миграции нужно применить заранее.

## База знаний Bitrix24

Источником документации является официальный репозиторий:
https://github.com/bitrix-tools/b24-rest-docs

Парсер скачивает репозиторий, выбирает необходимые разделы документации, очищает Markdown и подготавливает документы для загрузки в Yandex AI Studio.

Основные разделы:

* `first-steps`
* `api-reference`
* `tutorials`
* `settings`
* `local-integrations`
* `sdk`

## Создание Search Index

Для первоначального создания базы знаний выполнить из корня проекта:

```bash
python scripts/kb_build.py
```

Команда:

1. скачивает документацию Bitrix24;
2. обрабатывает Markdown-файлы;
3. подготавливает документы;
4. загружает их в Yandex AI Studio;
5. создаёт Search Index;
6. сохраняет полученный ID в `.env`.

После успешного выполнения в `.env` появится:

```env
YA_SEARCH_INDEX_ID=...
```

Создание индекса может занять некоторое время.

При обновлении документации команду можно запустить повторно:

```bash
python scripts/kb_build.py
```

При этом будет создан новый Search Index с актуальной версией документации.

## Запуск бота

Запускать приложение из корня проекта:

```bash
python -m app.main
```

При успешном запуске будут инициализированы:

* Vosk;
* база данных;
* Telegram-бот.

После этого бот готов принимать сообщения.

## Работа бота

Пользователь может отправить:

* текстовый вопрос;
* голосовое сообщение.

Для текстового сообщения запрос передаётся в сервис ассистента.

Для голосового сообщения:

```text
Telegram
→ получение аудио
→ Vosk
→ распознавание текста
→ поиск по документации
→ YandexGPT
→ ответ пользователю
```

Ответ формируется на основе информации, найденной в базе документации Bitrix24.

Базовая проверка работоспособности бота через консоль:
```bash
python -m scripts.setup_questions
```

## Обновление документации

Если документация Bitrix24 обновилась, достаточно выполнить:
Для консоли:
```bash
python scripts/kb_build.py
```
Для телеграмма:
```text
/rebuild_kb
```
После завершения команда сохранит новый `YA_SEARCH_INDEX_ID` в `.env`.

Старый индекс при этом не используется новым запуском, если переменная окружения была успешно обновлена.

## Ограничения Yandex AI Studio
Search Index имеет квоты на количество запросов в единицу времени. При превышении лимита API может вернуть служебный ответ вида:

```text
fair_usage_limit:search_index
{"searchQuery":"..."}
```
В этом случае стоит подождать и повторить запрос позже, либо проверить квоты и баланс в консоли Yandex Cloud. Бот распознаёт такие ответы и не показывает их пользователю.

## Безопасность

API-ключи Yandex Cloud, токен Telegram и данные подключения к базе данных должны храниться только в переменных окружения.

## Назначение проекта

Проект предназначен исключительно для помощи разработчикам при работе с документацией Bitrix24 API.

Основная задача системы — быстро находить релевантную информацию в документации и предоставлять её пользователю в удобной форме через Telegram.
